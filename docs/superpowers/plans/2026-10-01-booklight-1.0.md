# Booklight 1.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Take Booklight from the 0.1 proof to 1.0: the full launcher with a glass panel that is motion-designed throughout, opt-in web suggestions, settings, three languages, and a signed release that goes to GitHub and to Google Play closed testing.

**Architecture:** Unchanged from the spec: a pure-Kotlin `core/` (matching, ranking, learning, sums, web rules) under JUnit, and a Compose `app/` whose launcher activity is a see-through window sized to the panel. 1.0 adds preferences, a network suggestions source that the model merges in after the local results, an AGSL glass surface, and one motion system (`overlay/Motion.kt`) that every transition goes through.

**Tech Stack:** Kotlin 2.4.20, AGP 9.4.1, Compose BOM 2026.09.00, material3 1.5.0-alpha29, kotlinx.serialization, `RuntimeShader` (API 33+), `HttpURLConnection`. minSdk 34, target/compile 37.

**Spec:** `docs/superpowers/specs/2026-10-01-booklight-design.md`, as amended by Alex's answers on 2026-10-01 (recorded in `docs/PLAN.md` §11 and listed under Global Constraints here).

## Global Constraints

- Alex's answers (2026-10-01): name Booklight; suggested key "the key left of Space + Space, and Action + K if several are possible"; nothing shown when nothing is typed; Esc closes at once; internet for suggestions; small calculator (Summa as an extension in 2.0); extensions are the way to grow; advanced tiers as planned; repo private until the first release, then public; Android 14+ (minSdk 34); US English, British English and German; Action + K stays on his HP; fix BentoBar.
- His design brief for 1.0: more transparency and more blur; a glass effect with refraction if possible; "highlights move and lists animate in and not just pop"; "uniquely well motion designed"; a small first run below the search box; a tasteful G in place of the magnifier when the engine is Google.
- Device fact (checked 2026-10-01): a custom shortcut must include the Action key. Alt + Space and Ctrl + Space are not accepted, Action + Space is taken, **Action + Alt + Space is accepted**, and an app has one custom shortcut. So the app suggests Action + Alt + Space, with Action + K as the alternative.
- Manifest permissions: `INTERNET` only. No runtime permissions, no accessibility service, no overlay permission. `android.hardware.touchscreen` not required.
- Web suggestions are **off until the user turns them on**, from the first-run card or settings, after reading what is sent and to whom (Play's User Data policy; the Play session's advice). The app, `store-submission/forms/data-safety.md` and the privacy page must say the same thing.
- One panel, one ranked list, row one selected, Enter runs it. At most 8 rows. The window is exactly the panel.
- Every user-facing string is a resource, in `values/` (US English), `values-en-rGB/` (only where spelling differs) and `values-de/`.
- No Claude attribution in commits or code. versionCode 1, versionName "1.0". Release key `~/.config/booklight/keystore.jks`, alias `booklight`, SHA-256 `61:30:F1:F9:11:56:11:56:5D:20:60:08:48:59:02:2C:E8:12:A4:35:E7:BC:62:76:69:D5:C3:66:86:90:A7:F6`.
- **Do not push the `v1.0` tag until the Play session confirms app signing is set** (a bundle uploaded first would make Google generate its own key).
- HP rules: `./bl idle` before opening the panel; never `uiautomator`; never the Debian VM; `./bl screen` pictures are never published.

## Review Focus

1. **Suggestions arrive late or not at all** (offline, slow network, a reply for older text): the list must never wait, never show suggestions for text that is no longer in the field, and never crash on a malformed reply. Test: `SuggestTest` (parser) and `OverlayModel` discarding stale replies.
2. **Typing faster than the list animates**: rows keyed by id must settle on the right list with the first row selected. Check on the HP with `input text` bursts and a screen recording.
3. **A long list on a short window** (a small external display, 200 % scaling): the panel must stay on screen. Test: `Metrics.maxRows(screenHeight)` in `MetricsTest`.
4. **Text that is not a sum, an address or a keyword but looks like one** ("e", "1.5", "g" alone, "yt" alone, "maps.me"): Test: `CalcTest`, `WebTest`, `SitesTest`.
5. **Blur off / reduced motion / dark theme**: the panel must stay legible with the solid surface, cut instead of animate when the system's animator scale is 0, and hold contrast in dark. Check on the HP by toggling each.

### Task 1: Core: sites, engines, suggestions, completion, effects

**Files:** Modify `core/.../Model.kt`, `SearchEngine.kt`, `Web.kt`; create `core/.../Sites.kt`, `Suggest.kt`; tests `SitesTest.kt`, `SuggestTest.kt`, `WebTest.kt`, `SearchEngineTest.kt`, `MatcherTest.kt`.

**Interfaces (produces):**
- `Kind.SUGGESTION`; `Effect.StorePage(packageName)`; `Effect.SiteSearch(url)` is not needed (an `OpenUrl`).
- `data class Engine(id, name, searchUrl, suggestUrl)`, `Engines.all`, `Engines.byId(id)`, `Engine.search(text): String`, `Engine.suggest(text): String`. Templates use `%s`.
- `data class Site(keyword, name, url)`, `Sites.defaults`, `Sites.parse(text, sites): Pair<Site, String>?` (the keyword must be followed by a space and text).
- `Suggest.parse(body: String, limit: Int): List<String>` for the OpenSearch reply `["text",["a","b"]]`; anything else gives an empty list.
- `Matcher.completion(query, title): String?` = the rest of `title` when it starts with `query` (ignoring case and accents), else null.
- `SearchEngine.merge(local: List<Result>, suggestions: List<Result>, limit: Int = 8): List<Result>`: locals first, then at most 3 suggestions, then the fallback row last; locals give way so that suggestions and the fallback fit.

- [ ] Tests first for each of the above (tables of inputs and non-inputs), run red, implement, run green (`./bl test`), commit.

### Task 3: Providers and executor

### Task 5: Glass, motion and the panel

**Files:** create `overlay/Glass.kt` (AGSL surface), `overlay/Motion.kt` (specs, reduced motion); rewrite `overlay/OverlayUi.kt`; modify `overlay/OverlayActivity.kt`, `ui/Icons.kt`.

- **Glass:** tint at about 55 % over a 64 dp window blur; an AGSL shader draws the tint, a lamp glow under the top edge, a bright bevel along the rim with a faint prismatic fringe, and fine grain. The bevel's highlight follows the pointer. Solid surface when blur is off.
- **Motion** (all springs from `Motion`; cuts when the animator scale is 0):
  - Summon: the glass comes into focus (blur and dim 0 → full) while the panel scales 0.96 → 1 and a light sweep crosses the rim.
  - The window's height follows a spring; rows enter staggered (rise 10 dp, fade), leave by fading, and move to their new place when the list changes.
  - One selection pill glides between rows; its leading edge moves faster than its trailing edge, so it stretches and settles.
  - Results ↔ actions slide on a shared axis.
  - An answer's digits roll; "Copied" replaces the hint; running a row presses the pill, then the panel fades out with the blur.
- **Field:** the G mark when the engine is Google, else the magnifier; grey completion text after the cursor; a site chip for keyword searches.
- **First-run card** under the field while nothing is typed: the shortcut step, then the suggestions step (what is sent, to whom; Turn on / Not now).
- **Access:** rows are selectable items with their kind and action; the field is labelled.
- [ ] Build, check each state on the HP with `./bl shot` and a screen recording stepped frame by frame, tune, commit.
