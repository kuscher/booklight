# Booklight 2.0 implementation plan

**Goal:** build everything in `docs/superpowers/specs/2026-10-01-booklight-2.0-design.md` as one release, 2.0.

**Architecture:** as 1.1. `core/` (pure Kotlin, JUnit) gains places, note text, prompts and the model's new
effects; `app/` gains three providers (other apps' commands, the system's keys, the guide), six scopes, the
row's second line, the tip card, the pinned window and the window's left column.

**Spec:** `docs/superpowers/specs/2026-10-01-booklight-2.0-design.md`. Read with it: `docs/design/booklight-2.0.html`
(the pictures), `docs/design/design-system.md` (tokens, the motion table), `docs/design/ux-model.md` (keys),
`docs/research/device-findings.md`, `docs/research/next-features.md` (§4 for extensions).

**How it is executed:** in the main session, task by task, each committed working on `main`. One side job is
done already (the keys table, task 6). A design reviewer and a code reviewer read the whole diff at the end, as
for 1.0 and 1.1; their must-fixes and should-fixes go in before the tag.

## Global constraints

- Permissions are exactly 1.1's four plus `android.permission.USE_PINNED_WINDOWING_LAYER`. Nothing that runs in the
  background, no accessibility service, no new `<queries>`.
- No other app's process is started before Enter; nothing typed is handed to another app.
- Every user-facing string is a resource, English and German. Copy is plain.
- The window is exactly the panel; `Metrics.height(model)` must equal what `Panel` draws, the open second line
  and the tip card included.
- All motion specs come from `Motion.kt`; nothing pops; with the system's animations off everything cuts.
- One highlight per level, and it travels: the column's, the list's, the row's (across its two lines).
- No attribution lines in commits or code. Device rules in `CLAUDE.md` hold on the Lenovo as on the HP.
- `Place` only grows at its end: recipes store a place by its number.

## Review focus

1. Another app's intent: started only when it resolves to an exported activity of the declaring package that needs
   no permission; no grant flags, clip data or selector survive; a hostile XML file (huge, deeply nested, a
   keyword that is Booklight's) costs nothing and takes nothing over.
2. The second line: a row that keeps its id and loses actions while typing; arming past the ninth and back; a held
   Tab; Ctrl + digit and arrows never reach Uninstall.
3. `s` and `k`: Tab on a keyword enters the scope only for the text on screen; `s`, Enter still opens an app; a
   user's own link called `s` or `k` keeps working (the user's keyword wins).
4. Notes files: the folder revoked, a file edited by hand (no final line break, Windows line ends, a very large
   file), Todo.md missing; ticking the same task twice; nothing read unless a notes scope is open.
5. The pinned window: the layer refused (the Lenovo, another build), a second pin, a countdown past zero, the
   window closed with the timer running, rotation of theme and language while it is open.
6. Tips and first-run cards never both; Enter on a tip types, never runs; "No tips" really turns them off.
7. The window: the column at 720 dp and under, the keys between column and page, "Edit…" from the panel still
   lands on the right item, animations off, dark, German.

## Core API (task 1)

```kotlin
// Model.kt
enum class Place { NONE, LEFT, RIGHT, LEFT_THIRD, MIDDLE_THIRD, RIGHT_THIRD, LEFT_TWO_THIRDS, RIGHT_TWO_THIRDS,
                   TOP_LEFT, TOP_RIGHT, BOTTOM_LEFT, BOTTOM_RIGHT, CENTER, FULL }
sealed interface Effect {
    LaunchApp(packageName, className, user = 0, place = Place.NONE, newWindow = false, display: Int = 0)   // 0 = wherever
    // StorePage is removed
    Open(owner: String, intent: String)                   // another app's command: an intent: URI, checked by the Executor
    Pin(kind: String, text: String, value: Long = 0, note: String = "")   // text | answer | color | qr | timer
    AppendNote(text: String, file: String = "")           // "" = Notes.md, TODAY = the day's file, else that file
    AddTodo(text: String); TickTodo(text: String); OpenNote(file: String)
    Type(text: String)                                    // puts text in the field; the panel does it itself
}
sealed interface Body { /* … */ Keys(keys: List<String>) }   // a key combination, drawn as caps

// Places.kt
data class Box(val left: Int, val top: Int, val right: Int, val bottom: Int)
object Places { fun bounds(place: Place, area: Box): Box? }

// NoteText.kt: the text of the notes files, with no Android in it
object NoteText {
    fun entry(text: String, stamp: String): String            // "- 2026-10-01 14:02  first\n  next\n"
    fun todo(text: String): String                            // "- [ ] text\n"
    fun find(content: String, query: String, limit: Int): List<NoteLine>   // newest first
    fun open(content: String): List<String>                   // tasks not ticked, in file order
    fun tick(content: String, task: String): String?          // the file with that task ticked; null if not there
    fun target(arg: String, files: List<String>): Pair<String, String>?   // "ideas better…" → ideas.md, "better…"
}
data class NoteLine(val text: String, val date: String)

// Prompts.kt
object Prompts { fun fill(prompt: String, text: String): String }   // {text}, or the text after the prompt

// Verbs.kt: a verb may be three words ("left two thirds"); a whole word beats the start of a longer one
```

## Tasks

- [ ] **1. Core.** The API above with tests: `PlacesTest` (every place tiles the area, odd widths, an area with an
  offset), `NoteTextTest` (entries, hand-edited files, CRLF, tick twice, target), `PromptsTest`, `VerbsTest`
  gains three-word verbs and "left" beside "left third". `Effect.StorePage` and its users go. The app is updated
  so it still builds.
- [ ] **2. Places.** `AppsProvider`: the seventeen actions in the spec's order, verbs for each place in
  `strings` (English and German), `… on display N`. `Executor`: bounds from `Places`, `setLaunchDisplayId`.
  `Recipes` holds the new places. Symbols for each place (a window with the part filled).
- [ ] **3. The row's second line.** `OverlayModel`: which actions are on which line (nine, then the rest), the
  line is open when the arming is on it; `Metrics.rowHeight` takes it; `Strip`: the arrow, two lines, one pane
  that travels between them, the cascade; `Rows` and the pill follow the height. Keys per the spec.
- [ ] **4. Other apps' commands.** `providers/AppCommands.kt`: the index (manifest shortcuts through
  `Intent.parseIntent`; the Booklight file), rebuilt when the app list is; the provider; scopes from files in
  `Scopes.all()` after the user's own; `Effect.Open` in `Executor` with its checks; `Settings.appCommands`,
  `Settings.mutedApps`. Debug fixture: `app/src/debug/res/xml/booklight_commands.xml`. `docs/EXTENSIONS.md`.
  The throwaway `shortcuts` probe is deleted.
- [ ] **5. `s`, `k` and Tab on a keyword.** `SettingsScope` (the pages, the hand-over row; more pages added to
  `settings_pages.xml` and checked on the device; whether the Settings search takes the text is tried there),
  `KeysScope`; `OverlayModel.fill()` and `Panel`'s Tab take a keyword that is the whole text; the footer's hint;
  one-letter keywords rank under apps.
- [ ] **6. The system's keys.** `res/values{,-de}/keys_table.xml` (done; read through once, the four the side
  job was unsure of settled), `KeysProvider`, `Body.Keys` in `Rows`/`Bodies`, `Settings.showKeys`.
- [ ] **7. Notes.** `data/Notes.kt`: list, read (kept for a moment while a scope is open), append to a file,
  tick. `NotesScope`, `TodoScope`, the second row and "Today" in `NoteScope`. Effects in `Executor`.
- [ ] **8. Prompts.** `Settings.prompts` (seeded from resources on first run and by the move to schema 3),
  a scope per prompt, rows in `TextScope`, the editor in the window.
- [ ] **9. Pin.** The permission; `pin/PinActivity` (compose, the app's theme, one Copy button, the countdown);
  `Effect.Pin` in `Executor` (launch bounds bottom right); Pin on sums, colours, QR codes, notes; "Start and pin"
  on timers; `PinScope`.
- [ ] **10. The guide.** `Guide.kt`: the table (sections, a name, an example, one line, the scope it enters),
  built from the scopes and a fixed list. `HelpScope` (`?`, `help`), `Effect.Type`, the "All commands" row.
- [ ] **11. Tips.** `Card.TIP` in the model (after the first-run cards, never in the stage's demo), the card with
  the tip's mark, "Try it" and "No tips"; `Settings.tips`, `Settings.tipAt`; the switch in the window.
- [ ] **12. The window.** `window/Nav.kt` (the column, its pill, icons only when narrow), `MainActivity` split
  into pages, keys between column and page, the page change; the Commands page from `Guide`; Results gains the
  system's keys and other apps; Yours gains prompts; "No key yet" (`Settings.keySeen`, set by `OverlayActivity`).
- [ ] **13. Finish.** German pass; TalkBack on the second line and the column; version 2.0 (code 3);
  `CHANGELOG`, `docs/release-notes/2.0.md`, `README`, `PRIVACY`, `docs/PLAN.md` §4/§6, `permissions.md`,
  `CLAUDE.md`, `PICKING-UP`, the store's release notes (English and German, under 500 characters) and the
  data-safety note; design-system.md and ux-model.md gain the second line, the column and the tip card.
- [ ] **14. On the device (Lenovo).** Every new row through `./bl debug keys`; the second line, the column's pill,
  the page change and the tip card stepped through frame by frame; the pinned layer (`dumpsys` for the task's
  layer); three of other apps' commands for real; places by `dumpsys activity` bounds; German; dark; a release
  build's start time.
- [ ] **15. Reviews, then the release.** Design review and code review of the whole diff, findings fixed, the
  checks of task 14 again for what changed. Then the tag `v2.0` (Alex: "build and upload to github when you are
  done"; "Tag v2.0, both"): the GitHub release, and a draft on Play's closed-testing track that waits for him.

Each task ends with: `./bl test` green, `./bl build` green, the feature driven once on the device with
`./bl debug`, a commit.
