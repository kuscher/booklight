# Booklight 2.0 implementation plan

*Second draft, after the three design reviews. Not approved yet.*

**Goal:** build everything in `docs/superpowers/specs/2026-10-01-booklight-2.0-design.md` as one release, 2.0.

**Architecture:** as 1.1. `core/` (pure Kotlin, JUnit) gains places, note text, prompts and the model's new
effects; `app/` gains three providers (other apps' commands, the system's keys, the guide), the scopes of §7 to
§11, a row's opened actions, the tip card, the pinned window, the window's column and, if Alex says yes, the
on-device model behind the prompts.

**Read with the spec:** `docs/design/reviews-2.0/ux.md` (the rules for every key; its §5 is the table of keys),
`visual.md` (its §5 is the component specs, in dp), `motion.md` (rows 21 to 55, and (c): what to check frame by
frame), `docs/design/booklight-2.0.html` (the pictures, at 1 px = 1 dp), `docs/research/on-device-ai.md`.

**How it is executed:** in the main session, task by task, each committed working on `main`. The keys table is
written already (task 6). At the end the same three reviewers look at the built app on the device's captures, and
a code reviewer reads the whole diff; their must-fixes and should-fixes go in before the tag.

## Global constraints

- Permissions are 1.1's four plus `USE_PINNED_WINDOWING_LAYER`, and AICore's `BIND_SERVICE` only if §13 is approved.
  Nothing that runs in the background: with §13, the library's uploader, its job service and its alarm receiver are
  removed in the manifest, and a test checks the merged manifest for them.
- No other app's process is started before Enter; nothing typed is handed to another app.
- Every user-facing string is a resource, English and German. Copy is plain.
- The window is exactly the panel; `Metrics.height(model)` equals what `Panel` draws. One writer of the window's
  height per frame. The window's width is never animated.
- All motion specs live in `Motion.kt` (the unfold's spring, `roll`, `type`, `tick` move there). Nothing pops; with
  the system's animations off everything cuts and the holds stay.
- One highlight per level, and it travels. No pane in an opened list; no fixed hues; no divider lines.
- `Place` only grows at its end: recipes store a place by its number.
- No attribution lines in commits or code. Device rules in `CLAUDE.md` hold on the Lenovo as on the HP.

## Review focus

1. Another app's intent: started only when it resolves to an exported activity of the declaring package that needs
   no permission; a hostile file (huge, nested, a keyword that is Booklight's or the user's) costs nothing.
2. An opened row: a row that keeps its id and loses actions while typing; a held Tab or → never opens or closes
   it; typing closes it in the same frame; Ctrl + digit and arrows never run Uninstall; the height never passes the
   screen.
3. Everything that fills the field for the user (Try it, `?`, a Commands row, a scope's row): the next Enter is a
   new press 350 ms later; that text is not kept as the last text.
4. `s`, `k`: Tab on a keyword only while the selection is untouched; `s`, Enter opens an app; "s bahn" still
   searches the web; a user's own `s` or `k` link wins.
5. Notes files: the folder revoked; a file edited by hand (no final line break, CRLF, very large); two equal
   tasks; tick, untick, tick; nothing read unless a notes scope is open.
6. The pinned window: the layer refused; the keys going back to the app in front; a second pin; zero; closed with
   the timer running; theme and language changing while it is open.
7. The on-device model, if in: not there, there but not downloaded, busy, over its quota, cancelled by typing,
   an answer longer than four lines; its rows never run anything; no uploader in the build.
8. The window: the column at every width from 720 to 1100 dp; Tab between column and page; "Edit…" from the panel
   still lands on its item; "No key yet" for a 1.1 user; animations off, dark, German.

## Tasks

- [ ] **1. Core.** `Place` (thirteen places), `Places.bounds` with tests; `Effect`: `Open`, `Pin`, `AppendNote(file)`,
  `AddTodo`, `TickTodo`, `OpenNote`, `Type`, `LaunchApp.display`; `StorePage` and its users go; `Body.Keys`;
  `NoteText` (entries, find, tasks by line, tick and untick, target file) with tests; `Prompts.fill`; `Verbs`:
  three-word verbs, a whole word before the start of a longer one, a one-letter last word leaves the name standing.
  `SearchEngine`: a command or app whose title starts with keyword and text comes first inside a scope; the row
  of a one-letter keyword keeps the last local place; nothing matches in `s`/`k`, the web row is first.
- [ ] **2. Motion's ground.** `Motion.kt` gains `open`, `roll`, `type`, `tick` and a debug-only slow factor for
  every spring and tween. The footer is anchored to the window's bottom edge. The opening's gate: the height is the
  field's until the glass is 85 % open. The closing draws in to the field's centre line. The check that draws
  itself (one composable). The title beside a strip: laid out once in a fixed box, with the fade.
- [ ] **3. Places and the row.** `AppsProvider`: the actions in the spec's order, short place names, verbs in
  English and German, "on display N". Symbols per `visual.md` §5.8. `Strip`: 32 dp pitch, slots keyed by action id,
  More as the last stop, the arrow's slot becoming a typed action, the pane going straight to its slot.
  `OverlayModel`/`Rows`/`Metrics`: the opened row (`block` as one value, the list reduced to the row and its
  actions, the 40 dp action rows, the pill's cover, the keys of `ux.md` M2). `Executor`: bounds, display. `Recipes`.
- [ ] **4. Other apps' commands.** `providers/AppCommands.kt` (manifest shortcuts through `Intent.parseIntent`; the
  Booklight file), the ranking rules of spec §3, scopes from files, `Effect.Open` with its checks,
  `Settings.appCommands` and `mutedApps`. Debug fixture and `docs/EXTENSIONS.md`. The probes of this session
  (`shortcuts`, the AI probe activity) are deleted or, for the AI one, replaced by task 8's code.
- [ ] **5. `s`, `k` and Tab on a keyword.** `SettingsScope` (more pages in `settings_pages.xml`, each checked on the
  device; the hand-over row), `KeysScope`, Tab in `Panel` and `OverlayModel` with the keyword's travel into the chip,
  the footer's hint, who owns a keyword (`Scopes`, the link editor).
- [ ] **6. The system's keys.** `keys_table.xml` (done; the four uncertain entries settled against the HP notes),
  `KeysProvider`, `Body.Keys` with the strip's room kept free, `Settings.showKeys`.
- [ ] **7. Notes.** `data/Notes.kt`: list, read (held while a scope is open), append to a file, tick and untick by
  line. `NotesScope`, `TodoScope` (the box, the tick, Undo, the row that stays), the second row and "Today's note"
  in `NoteScope`. The height holds until the first rows are read.
- [ ] **8. Prompts, and answers on this device.** `Settings.prompts` (seeded on first run and by schema 3), a scope
  per prompt, the clipboard's first line, rows in `TextScope`, the editor. If approved: `ai/OnDevice.kt` (status,
  warm-up at the chip, one request, cancel on typing, close with the panel), the streamed answer in the preview
  row, "Get the on-device model", Replace through `PROCESS_TEXT`'s result, the manifest removals and their test,
  the edge light while it works.
- [ ] **9. Pin.** The permission; `pin/PinActivity` per `visual.md` §5.7 (no bar of its own, Copy as a strip of
  one, the countdown on `tick`); focus given back after the layer is granted; `Effect.Pin`; Pin on sums, colours,
  QR codes, notes and found lines; "Start and pin"; `PinScope` with Unpin.
- [ ] **10. The guide and Booklight typing.** `Guide.kt` (one table for `?`, the Commands page and the tips),
  `HelpScope`, `Effect.Type` on the `type` cadence with one search at the end, the 350 ms guard.
- [ ] **11. Tips.** The card after the gate and 400 ms of nothing typed; the example as the field's placeholder;
  Tab arms; which tip is next, what counts as shown, the end of the pass; `Settings.tips`, `tipAt`, `tipsSeen`.
- [ ] **12. The window.** `window/Nav.kt` (the column, its quiet pane, its width following the window), the pages,
  Tab between panes and the two highlights, the page change after the pill, the Commands page, Results (keys,
  other apps), Yours (prompts), About (Forget last, Show the tips again), "No key yet" (`keySeen`, seeded for 1.1).
- [ ] **13. Finish.** German pass; TalkBack on the opened row and the column; version 2.0 (code 4);
  `design-system.md` and `ux-model.md` rewritten where 2.0 replaces them (rows 2, 3, the strip's widths, the type
  table, the table of keys, rows 21 to 55); `CHANGELOG`, release notes, `README`, `PRIVACY`, `docs/PLAN.md`,
  `permissions.md`, `CLAUDE.md`, `PICKING-UP`, the store's notes and the data-safety note.
- [ ] **14. On the device (Lenovo).** `motion.md` (c), all fifteen checks, with the slow factor; every new row
  through `./bl debug keys`; places by `dumpsys activity` bounds; the pinned layer; three of other apps' commands
  for real; German; dark; a release build's start time and size.
- [ ] **15. Reviews of the built app.** Use, look and motion on captures and recordings from the device; a code
  review of the whole diff. Findings fixed; task 14 again for what changed.
- [ ] **16. The release.** The tag `v2.0` (Alex: "build and upload to github when you are done"; "Tag v2.0, both"):
  the GitHub release, and a draft on Play's closed-testing track that waits for him.

Each task ends with: `./bl test` green, `./bl build` green, the feature driven once on the device with
`./bl debug`, a commit.
