# Booklight 2.0: design

*1 October 2026. On top of the 1.1 spec (`2026-10-01-booklight-1.1-design.md`). The ideas come from
`docs/research/next-features.md`; the numbers below are that report's top-fifteen numbers. The pictures are
`docs/design/booklight-2.0.html` (https://claude.ai/artifact/KXgB5p3eqEbYdLPCcDcWc3).*

- "let's call this version 2.0", "build and upload to github when you are done".
- "add a feature and command list into the settings app for Booklight and add a left nav to that app": §10.
- "another search provider with s and tab which searches all settings and a keyboard shortcut search provider i
  can enter with k and tab and search for all shortcuts - only add this if it is easy": §11. It is easy.
- "a tips option in settings which shows a tip of a function each time booklight gets invoked which looks the
  same way the keyboard shortcut reminder looks": §12.
- "update the animation when it closes to be the inverse from when it opens": done before this spec (design-system.md §4).
- His note that a fresh install has no key: Android gives no app a key; §10 makes the window say so.
- "can the app be clever about what is underneath to adjust the colors … Only if easy": it is not (an app gets
  no pixels from behind its own window); he chose to leave it out.

Not chosen, so not built: actions on a thing (2), colour from the screen (3), a key per command (10), packs (11),
Summa answers (12), text tools (13), the shelf (14), BentoBar answers (15). Live extensions (a provider asked per
keystroke) stay for a later release; 2.0 has the static layers only. The Gmail relay stays unbuilt.

**Permission.** One new one, with his tick: `android.permission.USE_PINNED_WINDOWING_LAYER` (normal: granted at
install, no prompt; `protectionLevel:normal` on the Lenovo). Nothing else changes; no new `<queries>`.

## 3. Other apps' commands

Two static layers; no other app's process starts before Enter, and no app sees what is typed.

**What apps already declare.** Each launcher activity's `android.app.shortcuts` XML (the items on its icon's
right-click menu) is read when the app list is read. A shortcut becomes a row if its last intent resolves to an
activity **in the declaring package** that is **exported** and asks for **no permission**. On the Lenovo: 28
declared, 19 usable (New tab, New event, New text note, New Window of the Terminal, My apps…). The Settings app's
are skipped: Booklight has those pages. Shortcuts apps make while running are the home app's to read, not ours.

**One file for Booklight.** An app adds to its `<application>`:
`<meta-data android:name="io.github.kuscher.booklight.commands" android:resource="@xml/booklight_commands"/>`

```xml
<booklight version="1">
  <command id="mini" title="@string/mini" keywords="@string/mini_words">
    <open action="io.github.kuscher.summa.MINI" class=".ui.MiniLauncher" />
  </command>
  <scope id="shot" keywords="shot,screenshot" name="@string/capture" hint="@string/capture_hint">
    <command id="area" title="@string/area"><open class=".CaptureActivity"><extra name="source" value="area" /></open></command>
  </scope>
  <scope id="pdf" keywords="pdf" name="@string/tools" hint="@string/tool_hint">
    <open class=".MainActivity" data="pdftoolbox://tool?q={argument}" />
  </scope>
</booklight>
```

- `command`: a row. `scope` with `command`s: a keyword, then fixed choices. `scope` with `open`: a keyword, then
  text that goes into the intent (`{argument}`, URL-encoded in `data`, as typed in an `extra`).
- Titles, names, hints and keywords may be string references, so they follow the app's languages.
- Unknown elements and attributes are skipped; a file with a higher `version` is read as far as it is understood.
- Documented in `docs/EXTENSIONS.md`. The debug build declares one for itself (it opens the backdrop), to test with.
- His own apps (StudioSnap, Summa…) each need a small release to carry such a file: not part of 2.0.

**Rows.** Kind "command"; the app's icon; title = the command; subtitle = the app's name. Found by the command's
name or keywords, by "app command" ("chrome new tab"), and, weakly, by the app's name alone (so "keep" lists Keep,
then its four notes).

**Running one.** `Effect.Open(owner, intent)`: the intent as an `intent:` URI. The `Executor` parses it and starts it
only if it resolves to an exported activity of `owner` that needs no permission; flags are its own (`NEW_TASK`),
no grant flags, no clip data, no selector. An extension's scope may not use a keyword Booklight or the user has.

**Switches.** Results page: "Commands from your apps" (on), then every app that offers any, each with its switch.

## 4. Pin

`Effect.Pin(kind, text, value)` opens `pin/PinActivity`: a small, opaque, ordinary window that asks Android 17 for the
pinned layer (`AppTask.requestWindowingLayer(WINDOWING_LAYER_PINNED)`), so it stays above other windows. One at a
time (the system's rule): a new pin replaces the old one. If the layer is refused the window stays, as a normal one.

| On | The window shows |
| --- | --- |
| `pin buy milk` (a scope) and Pin on a note | the text |
| a sum's answer | the answer, the sum under it |
| a colour | the swatch and its four forms |
| a QR code | the code |
| a timer: "Start and pin" | the countdown and its label; the Clock app's timer starts and rings |

The window is the app's theme, flat, with one Copy button where there is something to copy. Nothing runs when it is closed.

## 5. The system's keys

A table of the system's own shortcuts (`res/values/keys_table.xml`, English and German, 46 entries; from the
Welcome repo's device notes for the HP). `snap`, `desk`, `screenshot`, `lock` find rows that show the combination
as key caps. Enter opens Keyboard shortcuts; the second action copies the combination as text. They rank under
apps, settings and Booklight's own rows. A switch on the Results page turns them off. `k` is their scope (§11).

## 6. Places and the row's second line

`Place` grows: left and right third, middle third, left and right two thirds, the four quarters, centre, full.
The rectangles are arithmetic on the work area, in `core/Places.kt`, tested. "… on display 2" opens the app on that
display when there is one (`setLaunchDisplayId`). Recipes can hold the new places. A window that is already open
keeps its place, as in 1.1.

**A row shows nine icons at most.** With more, a tenth mark, an arrow, follows them; the rest wait on a second
line below. Moving the arming past the ninth (Tab, →, a click on the arrow) opens that line: the row grows from 56
to 96 dp on `place`, the icons of the second line arrive as a cascade, and the row's one highlight travels down to
them. The line closes when the selection or the text changes, or the arming moves back up. One highlight, never two.

An app's row, in order: Open · New window · Left half · Right half · Left third · Middle third · Right third · Full ·
App info | Left two thirds · Right two thirds · Top left · Top right · Bottom left · Bottom right · Centre · Uninstall
(last, in the error colour). **Store page is gone** (the action, its typed verb and its effect).

A typed place ("chrome top left", "files right third", "code full") arms that action; if it lives on the second line,
the row opens with the line showing.

## 7. The list of everything

`?` (or `help`) is a scope: every keyword and kind of row, with an example. Typing narrows it; Enter on a keyword
enters it, on anything else types the example. The panel has no scrolling, so its last row opens the full list in
the Booklight window (§10), which is built from the same table (`Guide`).

## 8. Notes

- `notes milk`: finds lines in Notes.md, newest first; nothing typed, the latest. Copy, or open the file.
- `todo call bank`: adds `- [ ] call bank` to Todo.md. `todo` alone lists what is open; Enter ticks one off.
- `note ideas better onboarding`: when the first word is the name of another `.md` file in the folder, a second
  row adds the rest to that file.
- The note row gains "Today": the line goes to a file named after the day (`2026-10-01.md`).
- All in the folder granted once in 1.1. Files are read when a notes scope is open, never otherwise.

## 9. Prompts

A prompt is a name, a keyword and a text ("Fix the spelling and grammar. Reply with only the corrected text:").
`fix their going too`, Enter: the Gemini app opens with the prompt and the text. With nothing typed it takes the
clipboard. The same prompts are rows for text another app hands over and for `clip`. Five to start with (Fix
spelling and grammar, Shorter, In German or In English by the device's language, Summarise, Explain); they are
edited in the window like snippets. `{text}` in a prompt says where the text goes; without it, it goes after.

## 10. The Booklight window

A left column of sections and one page beside it:

| Section | Holds |
| --- | --- |
| Booklight | the title and lead, the live stage, **Your key**, Tips |
| Commands | the list of everything (§7): sections, an example for each; Enter opens the panel with it typed |
| Yours | links, snippets, recipes, prompts |
| Look | theme, colours, glass, dim, opening |
| Results | search engine, suggestions, settings pages, sums, Ask Gemini, the system's keys, other apps |
| Access | notes folder, brightness, assistant key |
| About | what Booklight keeps, privacy policy, version |

- One highlight in the column that travels between sections (the list's pill, its two edges on two springs); the
  page changes with a short rise and fade. Under 720 dp of width the column is icons only.
- Keys: Up and Down move along the page's rows as before; Left from a row without a control goes to the column,
  where Up and Down change the section and Right or Enter go back into the page.
- **Your key.** Until the panel has once been opened the way a key opens it, the section says "No key yet" and the
  column marks it. Android never tells an app whether it has a key; this is the nearest truth.

## 11. `s` and `k`

Two scopes with one-letter keywords, entered as Chrome's address bar enters a site search:

- **`s`, Tab: Settings.** Every settings page Booklight knows (the 35 of 1.1 plus the ones the system offers that
  were missing, each checked to exist on the device). Typing narrows; the last row hands over to the Settings
  app's own search (`android.settings.APP_SEARCH_SETTINGS`), which is the only thing that knows every setting.
- **`k`, Tab: Keys.** The 46 system shortcuts of §5, with their key caps.

**Tab on a keyword.** When the field holds exactly a scope's keyword, Tab makes it the chip, whichever row is
selected; the footer says so ("tab Settings"). The keyword and a space does the same, as in 1.1. A one-letter
keyword's row ranks under apps, so `s`, Enter still opens the usual app. The longer keywords `settings` and `keys`
work too.

## 12. Tips

A switch, "Tips". With it on, and once the two first-run cards are done, the empty panel shows one tip each time it
opens, in the same card as the keyboard-shortcut reminder: a mark, a name ("Timer"), one line ("timer 10m tea
counts down in the Clock app"), and two answers: **Try it** (Enter: the example is typed for you) and **No tips**
(turns the switch off). Typing anything puts the card away. The tips come from the same table as §7, in a fixed
order, one after the other, and start again at the end.

## 13. Not in 2.0, noted

Live extensions and Summa's answers; BentoBar as the power pack; actions on files; the shelf; a key per command;
colours that follow what is underneath. `docs/research/next-features.md` §5 lists what to check on a device before those.
